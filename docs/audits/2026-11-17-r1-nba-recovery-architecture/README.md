# R1 — NBA recovery architecture decision

**Decision:** use verified stored evidence before live historical recovery. Retain the existing model and eligibility safeguards. Implement the small cache-first display improvement now; do not buy a feed or attempt another R1 deployment. Full cold-start independence needs complete current-season model inputs, not another private-preview investigation.

## Architectural failure, and what the fallback establishes

The model does not simply need a list of past point totals. `refreshBasketballObservations` discovers recent fixtures from player logs, then validates full official two-team box scores. `basketballModelObservations` requires reconciled player/team totals, minutes, attempts, turnovers, starter/usage context, fixture/season/team identity and a 48-hour availability lag. `basketballFeatureIndex` requires at least five eligible player appearances, three with positive workload, and five own/opponent team games, subject to existing role checks.

Those complete refreshed observations and raw summaries are currently held in bounded process caches. A cold isolate loses them. A failed current refresh explicitly withholds forecasts; the older embedded snapshot, chart points, saved bets and normalized final results cannot substitute for every missing feature. This is the structural availability gap. Changing a browser header cannot make missing persisted model evidence exist.

Reuse the previous fallback comparison rather than repeat it: fallback and candidate have the **same** NBA Points partition, 12,647 observations, SHA256 `115fb0e140b83907d42d8bb6bd1345fc8841b2478f112f40e2fc9045cf3c3f41`, snapshot digest `b45c4ce8bafb7395c4742c7a58572f1cf51dc137455df9fb16453a3c0fb88080`. Actual rollback browser evidence showed 25 Points rankings. It does **not** establish that the fallback has another complete history database or can regenerate all forecasts under unconditional provider denial. Prior athlete-specific cooldown, request-profile and exact cached-board recovery repairs remain intact. No provider-access investigation was repeated.

Preserve the fallback's useful principle: return existing legitimate decisions instead of making their presentation depend on another source refresh. Do not restore broad failure handling, unsupported redirects, fabricated baselines, changed probabilities or unbounded requests.

## Small repair implemented

Previously, the Worker checked NBA KV recovery **after** the expensive application request failed or returned empty. A valid cached board could therefore still wait behind history fetching, model work, deadlines or the NBA queue.

For Points, Rebounds, Assists, Threes, PRA, PR and PA, the shipping Worker now checks a valid cached board **first**. It returns the exact stored ranks, forecasts, probabilities, quote identities, prices and original timestamps. The response and NBA banner explicitly identify a retained snapshot rather than a new live quote. No new selection or probability is inferred; EV remains tied to the original evidence.

Default active-slate navigation has a separate short-lived `nba-active` **key prefix in the existing KV namespace**, populated only by successful default-route responses. Explicit-day/scheduled boards cannot seed that identity and unexpectedly replace an overnight active slate. No namespace, service, binding or migration is added. Existing explicit-day cache keys remain usable. The additional default key expires using the existing TTL and does not change acceptance ages.

Ten-minute board and fifteen-minute quote limits, fixture/day/market identity, pregame timing, player availability, full forecast evidence and kickoff boundaries remain enforced. The new fast path also requires a known daily slate lock strictly after capture and the current time: a filtered board containing only late players cannot bypass the earlier whole-slate lock. Unknown/passed locks return to the application for normal frozen-history handling. Expired, wrong-day, future, started, malformed or unsupported rows fall through to existing recovery/unavailable behavior. Empty/error refreshes cannot overwrite the last valid cache. First Basket, Q1, NFL, NHL, capture/grading jobs and research code retain their existing paths. Capture invokes the application handler directly, so this presentation fast path does not short-circuit collection or checkpoint work.

## Practical alternatives and cost

| Approach | Reliability | Effort | Additional monthly subscription |
| --- | --- | --- | --- |
| **Stored-evidence-first display (implemented small step)** | Removes recovery dependency while a valid snapshot exists; survives cold isolates with existing KV. Cannot invent a board after expiry or on an unseen slate. | Small, existing infrastructure | **$0 new subscription.** One extra expiring KV publication for an uncached successful default board; existing metered KV operations/quotas still apply. No plan change. |
| Persist complete validated official fixture censuses; refresh in bounded background jobs | Addresses the structural cold-isolate gap once sufficient legitimate recent evidence is collected. Remains dependent on source availability for new games and accurate current context. | Moderate: provenance/versioning, bounded reads, freshness and completeness checks, reconciliation and offline/outage acceptance | **$0 new provider subscription** if the existing authorized official source supplies the required data. Existing storage/request usage applies; capacity must be checked before activation. |
| Replace the current model with averages or chart-only history | Does not meet the current model/probability/EV requirements; changes model design and needs independent validation | Substantial model and validation work | No necessary feed purchase, but **rejected** for R1; not a safe recovery repair. |
| Add another paid provider | Can help only if its authorized plan supplies complete needed census/context fields; not proven by another props subscription | Integration, entitlement and matching validation | Unknown/unquoted; **not recommended or purchased**. Existing data gaps do not justify spending yet. |

**One recommended direction:** decouple display from live history requests, using verified stored data first. This commit delivers its smallest safe display step. The next bounded implementation should retain complete validated official fixture censuses in existing dashboard storage and reuse those actual inputs after restart, with the same model and safeguards. Do not use picks, scalar chart observations or probabilities as substitutes for missing actual statistics.

An external **source of new complete official statistics** and current sportsbook quotes remains necessary for fresh predictions. That does not imply a new external **vendor or subscription**. OWL can supply existing authorized quotes; it does not replace missing minutes/attempts/usage/team census. Restoring ESPN access alone is also insufficient until actual complete observations are retained and coverage is verified. No live sports feed was queried, purchased or switched in this review.
